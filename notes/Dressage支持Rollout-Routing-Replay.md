### 核心结论
**R3 将训练-推理 logprob 绝对差异稳定降低约 60.5%**，从平均 0.0195 降至 0.0077，且在整个训练过程中保持高度一致的降幅。额外时间开销约占 step 总时长的 7.1%，性价比显著。

---

### 一、Logprob 一致性收益（核心指标）
R3 通过在训练前向传播时 replay 推理阶段的 MoE routing 决策，消除因路由不一致导致的 logprob 偏差。

| 指标 | 均值 | 最小值 | 最大值 |
| --- | --- | --- | --- |
| **不开 R3** (`without_replay`) | 0.01946 | 0.01440 | 0.02566 |
| **开启 R3** (`with_replay`) | 0.00765 | 0.00553 | 0.01022 |
| **绝对降幅** (`reduction`) | 0.01181 | 0.00887 | 0.01543 |
| **相对降幅** | **60.5%** | 58.7% | 62.3% |


#### 逐步降幅趋势
```plain
Step  without_replay  with_replay  reduction  降幅比例
────  ──────────────  ───────────  ─────────  ────────
  0       0.02130       0.00860     0.01269    59.6%
  5       0.01852       0.00745     0.01107    59.8%

```

**关键观察**：

+ 降幅比例从 step 0 的 59.6% 逐步上升到 step 27 的 61.3%，说明 **R3 的收益随训练推进略有增强**
+ 标准差极小（约 1%），表明 R3 的效果 **极其稳定**，不依赖特定数据分布

---

### 二、MoE 路由不一致分析
Qwen3.5-35B-A3B 具有 40 层 MoE（256 experts, top-8），推理与训练间的路由决策天然存在差异：

| 路由不一致指标 | 均值 | 含义 |
| --- | --- | --- |
| **element_mismatch_rate** | 45.25% | 每个 (token, layer, slot) 三元组中，约 45% 的 expert 选择不同 |
| **token_mismatch_rate** | 85.16% | 约 85% 的 token 至少在某一层存在路由差异 |
| **set_token_mismatch_rate** | 59.64% | 即使忽略 top-k 内的排列顺序，仍有约 60% 的 token 选择了不同的 expert 集合 |


**这组数据解释了为什么 R3 能带来如此大的收益**：MoE 模型中路由不一致是普遍且严重的，绝大多数 token 在训练和推理时走了不同的 expert 路径。R3 通过 replay 推理路由，直接消除了这一噪声源。

### 四、性能开销分析
R3 在训练阶段引入了一次额外的前向传播（`r3_fallthrough`），用于获取不使用 routing replay 时的 logprobs 作为对比基线：

| 时间组成 | 均值 | 占 step_time | 占 train_time |
| --- | --- | --- | --- |
| **r3_fallthrough** | **108.1s** | **7.1%** | **17.0%** |
| ref_log_probs | 150.7s | 9.9% | 23.7% |
| log_probs (with R3 replay) | 85.4s | 5.6% | 13.5% |
| actor_train | 290.2s | 19.1% | 45.7% |
| **train_time 合计** | **634.8s** | 41.7% | 100% |
| rollout_time | ~270s | ~17.7% | - |
| **step_time 合计** | **1521.6s** | 100% | - |


**关键说明**：

+ `r3_fallthrough` 的 108.1s 中，大部分是 **调试用的对比前向传播**，生产环境中可以关闭 `r3_fallthrough_log_probs` 来消除这部分开销
+ R3 replay 本身的开销已包含在 `log_probs` 的 85.4s 中（相比无 R3 时差异很小，因为 replay 只是替换路由决策而非增加计算量）
+ **生产环境中 R3 的实际额外开销接近 0**，因为 routing replay 只是在已有的前向传播中注入预存路由，不增加额外 pass

### 五、结论与建议
#### 收益总结
| 维度 | 评估 |
| --- | --- |
| **logprob 一致性** | ✅ 降低 60.5%，效果显著且稳定 |
| **训练稳定性** | ✅ clipfrac=0，grad_norm 稳定，kl_loss 可控 |
| **reward 提升** | ✅ raw_reward 从 0.42 提升至 0.65+（需 baseline 对比） |
| **性能开销** | ✅ 生产环境接近零开销（关闭 fallthrough debug 后） |
| **实现可靠性** | ✅ 28 步零 shape/record_count mismatch |


#### 建议
1. **推荐在所有 MoE 模型训练中默认开启 R3**，收益明确且开销可忽略
2. 生产跑批时关闭 `r3_fallthrough_log_probs` 调试 pass，节省约 108s/step
3. 后续可与不开 R3 的 baseline 在相同数据上做对比，量化 R3 对最终 reward/pass@k 的贡献
